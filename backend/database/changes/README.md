# 운영 DB 변경 이력

운영 DB는 자동 마이그레이션 도구를 사용하지 않고 검토된 SQL을 관리자가 직접 적용한다.

## 환경 정책

- 개발: `NODE_ENV=development`, `DB_SYNCHRONIZE=true`
- 운영: `NODE_ENV=production`, `DB_SYNCHRONIZE=false`
- 운영에서는 `DB_SYNCHRONIZE` 값과 관계없이 애플리케이션 코드가 synchronize를 비활성화한다.

## 파일 규칙

파일명은 `YYYY-MM-DD_NNN_설명.sql` 형식을 사용한다.

각 SQL 파일에는 다음 내용을 기록한다.

- 변경 목적과 대상
- 적용 전 확인사항
- 실행 SQL
- 검증 SQL
- 가능한 경우 롤백 SQL

## 적용 절차

1. 운영 DB 백업 또는 복구 지점을 확보한다.
2. 적용할 스키마와 현재 구조를 확인한다.
3. SQL을 검토하고 가능하면 트랜잭션 안에서 실행한다.
4. 변경 결과와 애플리케이션 동작을 확인한다.
5. 적용 일시와 적용자를 배포 기록에 남긴다.

운영에 적용한 SQL 파일은 수정하지 않는다. 후속 변경이나 롤백이 필요하면 새로운 SQL 파일을 추가한다.
